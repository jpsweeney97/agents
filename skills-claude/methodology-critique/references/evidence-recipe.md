# Evidence Recipe

Phase 1 of `methodology-critique`. Everything here is read-only contact with the evidence; nothing outside this repo moves.

## Surfaces

- Bundle: every file in the target directory, plus companion metadata where present.
- History: `git log --follow` across the bundle; read the founding version and every substantive diff. Name the provenance shape honestly — imported whole, mined/assembled, squad-born, founding-rewritten, or a shape the arc has not seen — because the shape sets what counts as the method's own record.
- Consumers: grep the repo for the skill name and its distinctive phrases; list every live routing surface as `path:line`. These price any rename and locate the transfer seams.
- Method context: `agent-facing-design` whole (the two-bars lens and Library Conventions govern the repairs); the neighbors the target routes to, routes from, or defines itself against; any doc contract the target's artifacts serve.

## Fire corpus

- Claude side: the skill-usage ledger (`~/.claude/logs/skill-usage-ledger.jsonl`); recover transcripts via the entries' session IDs.
- Codex side: rollouts under `~/.codex/sessions/`. Match on 2-3 body-only markers — distinctive sentences from the target's body, each verified unique among live sources by grepping this repo first. Never match on the skill name or description: roster injection puts those in every session.
- Classify every match: genuine fire (full or partial cycle) or detection noise (a session that merely read the text — a review, an audit, the import commit — or a marker shared with a sibling). Body-loaded proves the body was in context, not a completed run — classify what each transcript actually contains, and count venues honestly.
- Privacy: fires in the career repo or the personal wing are read for method behavior only. The committed critique may quote method moves, never personal or career substance; that stays in `~/personal` and `/Users/jp/career`. Read-only contact — nothing in those repos moves.
- Zero fires is a legitimate corpus: substitute the birth record (squad workflow journals, founding handoffs) where one exists, and test the method against its text, its birth, and the ecosystem that routes to it. Ledger silence is prune input elsewhere, never this treatment's verdict — a methodology critique is not a keep/prune deliberation.

## Rig

- Fan out with a small dynamic workflow, and only when the corpus earns one — a handful of transcripts is an inline read, not a fan-out.
- Keep the crew small: batch transcripts per reader (short or same-venue transcripts share a reader; only a genuinely long transcript gets its own), so a full corpus needs a handful of readers, not one each.
- Every agent this lane dispatches gathers evidence — the judgment is never delegated — so none inherits the session model. Sonnet at high effort is the proven default reader; escalate a single read to Opus only when Sonnet's classification of it comes back ambiguous or contradictory. The same rule covers re-runs and non-transcript evidence agents (history, consumers, method context).
- Return contracts: plain-Markdown headings, not strict structured-output schemas — schema-heavy returns from large transcript reads hit retry caps; re-run failed readers as direct agents.
- Re-verify firsthand: any floor breach, the strongest positive claims, and every finding the verdict will lean on. A reader's summary is testimony; the verdict cites what you re-read yourself.
