Best: **Tune the catalog fetch's request parameters**
Why: The fetch is the whole problem (E1: 4h05m median of a 4h43m job) and it is bound by request count, not the machine (E6: 6% CPU, 3.1 Mbps) and not concurrency (E9: more connections only raised 429s against the per-key 300/min limit). The job still uses the client-library default page_size of 50 (E4, E9), so it makes 41,869 requests for 2.09 million items (E5), while the API has allowed page_size 1000 since v3.2 on 2026-06-09 (E2), which would cut that to about 2,100 requests, a twenty-fold reduction in the rate-limited step. It is a one-line configuration change: no code, no procurement, no third party, no new spend, and maintainable by the current team, so it clears all three constraints and all three values. Every alternative that attacks the fetch harder is closed by evidence: no delta filter and no persistent identifiers (E2, E8), no second key, no quota increase, and bulk export only on an Enterprise tier costing ten to twelve weeks and $48,000 (E3), and the feed must reflect the 01:00 catalog so daytime polling is not allowed (E2, E7). The other in-budget options only trim minutes (concurrent pricing saves 24 to 31 minutes; starting earlier gains at most 15 minutes because the catalog is finalized at 01:00) and cannot by themselves fix a worst night of 5h41m against a 4h45m window (E1).
Runners-up, in order: **Run the pricing aggregation concurrently with the catalog fetch**, **Raise the job's timeout so it is never killed**, **Start the job earlier**
Unknowns that would change the choice: The evidence gives no per-request latency at larger page sizes, so if Corvid's response time scales close to linearly with page size, the gain shrinks toward nothing and the concurrency change becomes the primary lever. It is not stated whether the job's Corvid client library accepts page_size 1000 or caps it below the API maximum. If the 429 rate or response-size limits behave differently at page_size 1000, a smaller value such as 500 might be the safe setting, which would still be the same option.
