Best: **Use a shared calendar with sign-up slots**
Why: It runs on a system the pantry already has, so it clears all three constraints: no spending, no new staff, and volunteer data stays where an agreement already covers it. Bookable slots enforce capacity by construction, since a slot disappears once taken, so nobody turns up to a full shift, which the current email-and-spreadsheet flow and the group chat cannot guarantee. Open slots stay visible to the coordinator, so unfilled shifts are seen early enough to chase, and self-service booking removes the transcribing that eats the coordinator's hours. It can be set up well inside six weeks with no training beyond clicking a slot. The user's group-chat option fails the no-full-shift value because chat claims are unordered and uncounted, and it would move availability data into a place with no confirmed data agreement.
Runners-up, in order: **Rebuild the spreadsheet with validation and locking**, **Use the scheduling module of the pantry's donor-management system**, **Set fixed weekly shifts per volunteer**
Unknowns that would change the choice: Whether the pantry's existing data-protection agreement covers the calendar and whether that calendar product offers bookable appointment slots; if either fails, the spreadsheet rebuild becomes best. Whether the donor-management scheduling module is on the pantry's current plan at no cost with light setup; if so, it could overtake the calendar as the purpose-built option. Whether unstaffed shifts come mainly from no-shows rather than from nobody signing up; if no-shows dominate, reminders would need to accompany whichever tool is chosen.
