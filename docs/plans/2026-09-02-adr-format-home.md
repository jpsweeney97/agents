# ADR-FORMAT.md home: how `decision-record` joins `decide`

Date: 2026-09-02. Status: deliberated and approved; built as `decide` 1.1.0 (this document was revised to the deliberated text as part of that landing). The pre-deliberation text is commit `379a5ab`.

Question (left open by the 2026-09-02 plugin-bundle certificate, `docs/plans/2026-09-02-plugin-bundle-candidates.md` §Open): `decision-record` bound `../grill-with-docs/ADR-FORMAT.md` as the single source of the ADR format and forbade forking it, so it could not sit in the `decide` plugin. Where should that file live so `decision-record` can join?

## Deliberated answer (2026-09-02)

A cross-model deliberation with Codex (run `~/.synapsis/runs/2026-09-02-adr-format-home/`, readable `answer.md` beside the authoritative `run.json`) ended in a CONCESSION certificate: the host retired its pre-committed stance on three of the five sub-decisions after verifying Codex's evidence at `379a5ab`. The certificate's answer, in brief:

1. **The join is right if JP chooses it.** `decision-record` belongs in `decide` because of its job and routing: it creates the durable record after a decision and routes unsettled inputs to `making-recommendations`, `design-exploration`, or `ideate`. The 1.0.0 certificate excluded it only because its format file could not cross the plugin boundary. Session co-occurrence in the usage ledger (6 of 19 `decision-record` sessions with a `decide` member, 0 with `grill-with-docs`) is supporting evidence only.
2. **The canonical file moves to `plugins/decide/references/ADR-FORMAT.md`** with `git mv`. Codex receives only the plugin directory in its versioned cache, so a neutral repository path cannot stay a single source for a plugin skill; the file serves three skills, so plugin-level placement (the `plugins/handoff/references` precedent) is clearer than a directory under one skill.
3. **The old path becomes a git-tracked relative symlink, not a controlled copy.** It is single-sourced without a copy-synchronization script, an edit through it lands in the canonical, and it resolves under both kernel and lexical path resolution for every existing reference, which a direct plugin path from a standalone skill does not (fact 6 below). Because the integrity checker's check 2 extracts only `references/`, `scripts/`, `examples/` tokens and check 3 covers only per-skill support directories, the alias would sit outside every standing sweep; the build therefore adds check 6 to `scripts/check-library-integrity.sh`, asserting the alias keeps index mode 120000, is a working-tree symlink, has the exact relative target, and resolves to the canonical regular file, so deletion, conversion to a regular file, and retargeting all fail the sweep. This is the repository's first tracked symlink, proven on this macOS git checkout only.
4. **No pre-decided fallback.** If `grill-with-docs` is ever packaged, that plugin needs its own in-plugin copy (one Codex cache package cannot reach another package's source), standalone `improve-codebase-architecture` still needs a path that works through Claude's per-skill symlinks, and a resource-only `skills/grill-with-docs/` directory would be demanded as a managed link by `scripts/claude-skills-sync.sh`. The controlled-copy-with-drift-check precedent exists (`scripts/check-protected-set.sh`, a purpose-specific checker, not a reusable tool); the canonical-plus-copy topology is decided when that packaging is designed.
5. **`decide` goes to 1.1.0** (a new skill is a backward-compatible capability; the `git-cycle` 1.7.0 precedent for `land`), with the complete edit list: `decision-record`'s "Reuse the ADR format" paragraph; `grill-with-docs`'s maintenance note; `improve-codebase-architecture` unchanged; the manifest's version, description, shortDescription, longDescription, and a bare starter prompt; the README's skill list, arc description (`decision-record` as optional capture after a decision is made), conventions line, Writes table, and companion inventory; `TERMS.md` lines 5 and 7; `PRIVACY.md`; a 1.1.0 CHANGELOG entry; a dated note at the bundle plan's open decision 3; check 6 plus the check 2 extension in `scripts/check-library-integrity.sh`; and the two landings' proofs as recorded in the Procedure section below.

The certificate asserts the alias design resolves for every existing consumer reference under both runtime path layouts as tested here, that every named surface goes stale under the join, and that the future fallback is undecided. It does not assert that JP should make the join, that Claude's Read tool follows a file symlink (untested until the landing probe), that the alias works on any other checkout, or that anything is built. Setup disclosure: the question named this document, which argued the expected answer, so Codex's agreement on points 1 and 2 is partly induced by that anchor.

## Design gate (agent-facing-design, run before landing 1)

The increment adds one mechanism, check 6, and one deterministic mechanic, the alias. My read: the alias is a mechanic that pre-makes no semantic decision; check 6 is machinery, a validator. Evidence: the live checker (check 2's token regex, check 3's directory scope) and the scratchpad resolution tests. The lighter path, weighed for real: rely on the one-time landing probe plus the maintenance-note prose. It fails because prose cannot detect a later deletion or retarget, and the damage is silent: three skills lose their one format source, or a fork appears, with every standing sweep green. Machinery is justified by that failure mode and kept narrow: one path, four assertions, no new script. Whole-surface look: the checker grows from five owned checks to six, each a one-screen block; it is not larger than the wiring it protects. Verdict: machinery, justified for this increment; this is a ratification of a design already deliberated, said plainly, and it certifies nothing about the join's merit.

## Facts the design rests on

1. **Three consumers read the file.** `grill-with-docs/SKILL.md:96` links `./ADR-FORMAT.md`; `improve-codebase-architecture/SKILL.md:91` links `../grill-with-docs/ADR-FORMAT.md`; `decision-record/SKILL.md:24` linked `../grill-with-docs/ADR-FORMAT.md` and forbade relocating it "for no gain", flagging relocation as a future cleanup if `decision-record` proved the natural home for the ADR lifecycle.
2. **What the file is.** 531 words: convention detection, the template, the status vocabulary, numbering, the three-part gate, and what qualifies. `decision-record` consumes all of it and alone owns the lifecycle (status changes, supersession chains). `grill-with-docs` and `improve-codebase-architecture` consume the gate, template, and numbering to offer an ADR mid-session.
3. **Churn.** Three commits since the import (`5e52b7c` import, `b68b952` the `Revisit when` field, `3da8e35` the convention-detection fold on 2026-09-01). As a plugin file every future edit is a `decide` release: manifest bump, CHANGELOG, Codex republish, mirror on ask.
4. **Fire evidence** (`~/.claude/logs/skill-usage-ledger.jsonl` through 2026-09-02, Claude fires only, session co-occurrence not causation). `decision-record`: 19 sessions in 3 repos; 6 of them also fired a `decide` member (`making-recommendations` 3, `design-exploration` 3); 0 fired `grill-with-docs`; 0 fired `improve-codebase-architecture`. `grill-with-docs`: 31 sessions; 0 with `decision-record`; 2 with a `decide` member.
5. **The delivery boundary.** A plugin skill on Codex runs from `~/.codex/plugins/cache/turbo-mode/decide/<version>/`, a copy of the plugin directory and nothing else, so anything a plugin skill cites must be inside the plugin. Standalone skills run in place on Codex (`~/.agents/skills/<name>/`) and through a per-skill symlink on Claude (`~/.claude/skills/<name>` → `~/.agents/skills/<name>`; `~/.claude/skills/decide` → `~/.agents/plugins/decide`).
6. **Which path forms work from a standalone skill** (scratchpad test, 2026-09-02, both resolution modes). A file inside the skill's own directory always resolves. A sibling reference `../<skill>/<file>` resolves under kernel resolution (the physical parent is `skills/`) and under lexical resolution (the farm sibling exists). A direct `../../plugins/decide/references/ADR-FORMAT.md` resolves under kernel resolution but fails under lexical normalization on Claude (it becomes `~/plugins/...`). So no single path text for a plugin file works from a standalone skill on both runtimes without runtime-conditional wording.
7. **A relative symlink at the old path resolves in every case tested.** `skills/grill-with-docs/ADR-FORMAT.md → ../../plugins/decide/references/ADR-FORMAT.md` read in place, read through the Claude farm, read as a sibling from another farm entry, under both physical and lexical resolution. An edit made through the alias lands in the canonical. Git tracks it as mode `120000`; `git diff --check` is clean. The kernel resolves a symlink's own `..` against the link's physical directory, which is why the alias is immune to the problem in fact 6.
8. **Checker behavior.** `scripts/check-library-integrity.sh` check 2 validates only cited tokens that start with `references/`, `scripts/`, or `examples/` (with `../` prefixes). A root-level `ADR-FORMAT.md` is unvalidated by it. A `../../references/ADR-FORMAT.md` citation from inside the plugin is validated (the `handoff` precedent). A standalone citation containing `plugins/decide/references/...` produced a false dangle until this build extended check 2 to capture a plugin-qualified path whole and resolve it at the repo root (the `grill-with-docs` maintenance note names that path). Check 3 (orphans) covers only per-skill `references/`, `scripts/`, `examples/` directories, so a plugin-level `references/` is outside it, as `handoff`'s already is. Check 6 (added by this build) covers the alias.
9. **Precedents.** Plugin-level `references/` shared by several skills and carried into the Codex cache: `plugins/handoff/references/`. Controlled copies with a drift check: `scripts/check-protected-set.sh`, `scripts/check-review-family.sh`. Derived copies with drift reporting: `exports/` and `scripts/exports-drift.sh`. Tracked symlinks in this repo before this build: none. Adding a skill to a plugin is a minor bump (`git-cycle` 1.7.0 for `land`).
10. **Settled and not reopened here.** `decide`'s seven-skill membership was settled with `pressure-test` (where `grill-with-docs` belongs) separate because its skills challenge a position rather than form one. The certificate explicitly left the long-term home of `ADR-FORMAT.md` open; this document answers only that.

4. Mirror sync and push on JP's word (given with the approval).

## Risks and limits

- **First tracked symlink in the repo.** Any future script that walks with `find -type f` skips it; acceptable, because the alias is never the canonical. `skill-export` would need to dereference if `grill-with-docs` is ever exported (it is not today).
- **Claude's Read tool was not itself tested** before landing 1, only kernel and lexical resolution of the paths it would receive. The landing-1 live probe closes that.
- **Never put a symlink inside a plugin.** The Codex cache copy and the mirror sync would carry a link, not the file. Untested and avoided by construction: the real file is inside the plugin, the alias outside.
- **Release tax lands on two more surfaces.** `ADR-FORMAT.md` (3 edits in 3.5 months) and `decision-record` (4 commits since 2026-07-07) become `decide` releases.
- **Source and cache can differ** between a landed format edit and its republish: `grill-with-docs` reads the source through the alias, `decision-record` on Codex reads the cache. `AGENTS.md` already requires completing a landed bump promptly with `--publish`.
- **The join rests on job and routing, with co-occurrence as support.** Fact 4 is session co-firing on Claude only.
