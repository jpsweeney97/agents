## The claim and the scenario

**Behavior claim.** Given a decision in prose with a stated lean, hard constraints, values, and named files, the skill writes `00-setup.md` before the first dispatch, dispatches Generate, Prune, Shape, Recommend, and Contest as fresh agents in that order, each reading the previous stage's file; the briefs for Generate, Prune, and Shape omit the lean while Recommend's names it; Prune's records carry the five fields and keep field order; Shape proceeds under the delegated-selection statement without asking; the close arrives in the specified order with the cut ledger, the exclusion-check line, the run directory, the re-run offer, and what the run did not do.

**Scenario.** A real open question this repo holds: what to do with the shallow-prune safety experiment (T2), which closed INCONCLUSIVE on 2026-07-25 at 322 of 400 dispatches, now that deliberate 2.0 keeps a shallow Prune stage. The invoking prompt stated two hard constraints (well under T2's 15 operator hours; the AGENTS.md blind-evaluation rule), two values (knowing whether Prune is safe matters more than closing tidily; not another week of operator time), named four files, forbade web research, and planted a lean: "close T2 as unanswerable at acceptable cost and rely on watching real runs of the rebuilt skill instead." The lean and constraints were written by the smoke operator (this session), not by JP, to exercise lean withholding and Contest's preferred-exclusion rule; the question itself is real and was unresolved at run time.

## Deviations and observations

- **Setup not displayed before dispatch (partial).** The skill says to show the setup to the user in a few lines before the first dispatch. The orchestrator wrote `00-setup.md` and dispatched Generate without a text turn showing it. In `claude -p` mode intermediate text reaches no one, so this run cannot say whether an interactive session would skip it too. Predicted friction, unconfirmed; the skill text is unchanged pending an interactive observation.
- **Orchestrator read the three sibling skills itself** before composing briefs (three Read calls, about 5k tokens). Not required or forbidden by the skill; the briefs still pointed stage agents at the files rather than inlining them.
- **Harness memory writes.** After Contest, the orchestrator wrote two files under the headless project's `~/.claude/projects/<scratch-slug>/memory/` following the harness's own auto-memory instruction. Outside the skill's contract and outside any working tree; noted so nobody reads them as a skill behavior.
- **The lean was reclassified as a candidate.** The setup treated the lean sentence, which named a course of action, as a user-supplied candidate and withheld only that it was the favorite. This is the right reading of the Brief withholds column and matches Prune's "a candidate the user supplied dies only by a recorded cut"; it is recorded because a future reader may otherwise expect the sentence to be absent from the early briefs.
- **Run time exceeded the assessment's estimate.** The assessment predicted ten to twenty minutes; the run took 45. The time is stage thinking (each stage agent ran with extended reasoning on a 20-option field), not choreography. Corrected in the assessment by a dated note.

## What this run did not prove

One run, one runtime (Claude Code), one decision. Not exercised: the "don't add options" and "keep six" steering phrases; a constituent honest exit ending the run; the two Prune exits; the user-preferred excluded option rule in Contest (the user's candidate survived); the inline fallback where a runtime cannot dispatch fresh agents; a re-run from a middle stage; Codex. The recommendation's own quality was not judged by a second reader.
